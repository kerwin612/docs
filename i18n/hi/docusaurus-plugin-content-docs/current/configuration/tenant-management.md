# टेनेंट प्रबंधन

टेनेंट प्रबंधन सुविधा आपको कई टेनेंट बनाने और प्रबंधित करने की अनुमति देती है, जिनमें से प्रत्येक के पास अपने स्वयं के गेटवे कॉन्फ़िगरेशन और उपयोगकर्ता हो सकते हैं। यह दस्तावेज़ टेनेंट प्रबंधन कार्यक्षमता का उपयोग करने का तरीका बताता है।

## टेनेंट अवधारणा

टेनेंट MCP Gateway में एक महत्वपूर्ण अवधारणा है, जिसका उपयोग मल्टी-टेनेंट अलगाव को लागू करने के लिए किया जाता है। प्रत्येक टेनेंट:

- अपने स्वयं के गेटवे कॉन्फ़िगरेशन रख सकता है
- विशिष्ट उपयोगकर्ताओं से जुड़ा हो सकता है
- रूटिंग संघर्षों को सुनिश्चित करने के लिए अद्वितीय प्रीफिक्स पथों का उपयोग कर सकता है

डिफ़ॉल्ट रूप से, सिस्टम "default" नामक एक डिफ़ॉल्ट टेनेंट बनाता है।

## टेनेंट कॉन्फ़िगरेशन

गेटवे कॉन्फ़िगरेशन में, आप `tenant` फ़ील्ड का उपयोग करके निर्दिष्ट कर सकते हैं कि कॉन्फ़िगरेशन किस टेनेंट से संबंधित है:

```yaml
name: "example-gateway"
tenant: "default"  # टेनेंट नाम निर्दिष्ट करें

routers:
  - server: "example-service"
    prefix: "/api/example"
    # ...अन्य कॉन्फ़िगरेशन
```

## टेनेंट प्रबंधन संचालन

### टेनेंट बनाना

एक नया टेनेंट बनाते समय, आपको निम्नलिखित जानकारी प्रदान करनी होगी:

- **नाम**: टेनेंट के लिए अद्वितीय पहचानकर्ता, मौजूदा टेनेंट नामों को डुप्लिकेट नहीं कर सकता
- **प्रीफिक्स**: टेनेंट के लिए URL प्रीफिक्स, रूटिंग अलगाव के लिए उपयोग किया जाता है, अद्वितीय होना चाहिए
- **विवरण**: टेनेंट के लिए वैकल्पिक विवरण

अनुरोध उदाहरण:

```json
{
  "name": "tenant1",
  "prefix": "/tenant1",
  "description": "उदाहरण टेनेंट"
}
```

### टेनेंट अपडेट करना

आप निम्नलिखित टेनेंट जानकारी अपडेट कर सकते हैं:

- **प्रीफिक्स**: टेनेंट के URL प्रीफिक्स को अपडेट करें (अद्वितीयता सुनिश्चित करनी चाहिए)
- **विवरण**: टेनेंट विवरण अपडेट करें
- **स्थिति**: टेनेंट को सक्षम या अक्षम करें

अनुरोध उदाहरण:

```json
{
  "name": "tenant1",
  "prefix": "/new-prefix",
  "description": "अपडेट किया गया विवरण",
  "isActive": true
}
```

### टेनेंट हटाना

टेनेंट को हटाने से उस टेनेंट से जुड़े सभी कॉन्फ़िगरेशन हट जाएंगे। कृपया सावधानी बरतें, क्योंकि यह ऑपरेशन अपरिवर्तनीय है।

### टेनेंट क्वेरी करना

आप किसी विशिष्ट टेनेंट के बारे में विस्तृत जानकारी क्वेरी कर सकते हैं या सभी टेनेंट की सूची देख सकते हैं।

## टेनेंट-उपयोगकर्ता संबंध

टेनेंट को विशिष्ट उपयोगकर्ताओं से जोड़ा जा सकता है, जिससे निम्नलिखित सुविधाएँ सक्षम होती हैं:

- उपयोगकर्ता केवल उन टेनेंट तक पहुंच सकते हैं और उनका प्रबंधन कर सकते हैं जिनसे वे जुड़े हैं
- प्रशासक उपयोगकर्ताओं को कई टेनेंट एक्सेस अनुमतियां असाइन कर सकते हैं
- उपयोगकर्ता गेटवे प्रबंधन इंटरफेस में टेनेंट के बीच स्विच कर सकते हैं

## टेनेंट सेलेक्टर

गेटवे प्रबंधन इंटरफेस एक टेनेंट सेलेक्टर सुविधा प्रदान करता है, जो उपयोगकर्ताओं को निम्नलिखित की अनुमति देता है:

- उन सभी टेनेंट को देखें जिन तक उनकी पहुंच है
- वर्तमान संचालन के लिए टेनेंट के बीच स्विच करें
- वर्तमान टेनेंट के कॉन्फ़िगरेशन और स्थिति देखें

## रूट प्रीफिक्स सत्यापन

यह सुनिश्चित करने के लिए कि विभिन्न टेनेंट के बीच रूट संघर्ष न हों, सिस्टम प्रीफिक्स सत्यापन करता है:

- एक ही टेनेंट के भीतर रूट प्रीफिक्स अद्वितीय होने चाहिए
- विभिन्न टेनेंट के बीच रूट प्रीफिक्स संघर्षों से बचना चाहिए
- रूट बनाते या अपडेट करते समय स्वचालित रूप से सत्यापन किया जाता है

## सर्वोत्तम अभ्यास

- विभिन्न व्यावसायिक परिदृश्यों या टीमों के लिए अलग-अलग टेनेंट बनाएं
- पहचान और प्रबंधन को आसान बनाने के लिए सार्थक टेनेंट नाम और प्रीफिक्स का उपयोग करें
- सुरक्षा सुनिश्चित करने के लिए नियमित रूप से टेनेंट अनुमतियों की समीक्षा करें
- अलगाव बनाए रखने के लिए विकास और परीक्षण वातावरण के लिए अलग-अलग टेनेंट का उपयोग करें

# 테넌트 관리

테넌트 관리 기능을 사용하면 여러 테넌트를 생성하고 관리할 수 있으며, 각 테넌트는 자체 게이트웨이 구성과 사용자를 가질 수 있습니다. 이 문서에서는 테넌트 관리 기능을 사용하는 방법을 설명합니다.

## 테넌트 개념

테넌트는 MCP Gateway에서 중요한 개념으로, 다중 테넌트 격리를 구현하는 데 사용됩니다. 각 테넌트는 다음과 같은 특징을 가질 수 있습니다:

- 자체 게이트웨이 구성을 가짐
- 특정 사용자와 연결됨
- 라우팅 충돌이 없도록 고유한 접두사 경로 사용

기본적으로 시스템은 "default"라는 이름의 기본 테넌트를 생성합니다.

## 테넌트 구성

게이트웨이 구성에서 `tenant` 필드를 사용하여 구성이 속한 테넌트를 지정할 수 있습니다:

```yaml
name: "example-gateway"
tenant: "default"  # 테넌트 이름 지정

routers:
  - server: "example-service"
    prefix: "/api/example"
    # ...기타 구성
```

## 테넌트 관리 작업

### 테넌트 생성

새 테넌트를 생성할 때 다음 정보를 제공해야 합니다:

- **이름**: 테넌트의 고유 식별자, 기존 테넌트 이름과 중복될 수 없음
- **접두사**: 테넌트의 URL 접두사, 라우팅 격리에 사용되며 고유해야 함
- **설명**: 테넌트에 대한 선택적 설명

요청 예시:

```json
{
  "name": "tenant1",
  "prefix": "/tenant1",
  "description": "예시 테넌트"
}
```

### 테넌트 업데이트

다음 테넌트 정보를 업데이트할 수 있습니다:

- **접두사**: 테넌트의 URL 접두사 업데이트(고유성 보장 필요)
- **설명**: 테넌트 설명 업데이트
- **상태**: 테넌트 활성화 또는 비활성화

요청 예시:

```json
{
  "name": "tenant1",
  "prefix": "/new-prefix",
  "description": "업데이트된 설명",
  "isActive": true
}
```

### 테넌트 삭제

테넌트를 삭제하면 해당 테넌트와 관련된 모든 구성이 제거됩니다. 이 작업은 되돌릴 수 없으므로 주의하세요.

### 테넌트 조회

특정 테넌트에 대한 상세 정보를 조회하거나 모든 테넌트를 나열할 수 있습니다.

## 테넌트-사용자 연결

테넌트는 특정 사용자와 연결될 수 있으며, 다음과 같은 기능을 활성화합니다:

- 사용자는 연결된 테넌트만 액세스하고 관리할 수 있음
- 관리자는 사용자에게 여러 테넌트 액세스 권한을 할당할 수 있음
- 사용자는 게이트웨이 관리 인터페이스에서 테넌트 간 전환 가능

## 테넌트 선택기

게이트웨이 관리 인터페이스는 테넌트 선택기 기능을 제공하여 사용자가 다음을 수행할 수 있습니다:

- 액세스 권한이 있는 모든 테넌트 보기
- 현재 작업을 위한 테넌트 전환
- 현재 테넌트의 구성 및 상태 보기

## 라우트 접두사 검증

서로 다른 테넌트 간 라우트 충돌을 방지하기 위해 시스템은 접두사 검증을 수행합니다:

- 동일 테넌트 내 라우트 접두사는 고유해야 함
- 서로 다른 테넌트 간 라우트 접두사는 충돌을 피해야 함
- 라우트 생성 또는 업데이트 시 자동으로 검증 수행

## 모범 사례

- 다양한 비즈니스 시나리오나 팀을 위해 별도의 테넌트 생성
- 식별 및 관리가 용이하도록 의미 있는 테넌트 이름과 접두사 사용
- 보안을 위해 정기적으로 테넌트 권한 검토
- 개발 및 테스트 환경에 서로 다른 테넌트를 사용하여 격리 유지

# テナント管理

テナント管理機能を使用すると、複数のテナントを作成および管理でき、各テナントは独自のゲートウェイ設定とユーザーを持つことができます。このドキュメントでは、テナント管理機能の使用方法について説明します。

## テナントの概念

テナントはMCP Gatewayの重要な概念であり、マルチテナント分離を実装するために使用されます。各テナントは以下のことができます：

- 独自のゲートウェイ設定を持つ
- 特定のユーザーと関連付ける
- ルーティングの競合がないように一意のプレフィックスパスを使用する

デフォルトでは、システムは「default」という名前のデフォルトテナントを作成します。

## テナント設定

ゲートウェイ設定では、`tenant`フィールドを使用して設定が属するテナントを指定できます：

```yaml
name: "example-gateway"
tenant: "default"  # テナント名を指定

routers:
  - server: "example-service"
    prefix: "/api/example"
    # ...その他の設定
```

## テナント管理操作

### テナントの作成

新しいテナントを作成する際には、以下の情報を提供する必要があります：

- **名前**：テナントの一意の識別子、既存のテナント名と重複することはできません
- **プレフィックス**：テナントのURLプレフィックス、ルーティング分離に使用され、一意である必要があります
- **説明**：テナントのオプションの説明

リクエスト例：

```json
{
  "name": "tenant1",
  "prefix": "/tenant1",
  "description": "サンプルテナント"
}
```

### テナントの更新

以下のテナント情報を更新できます：

- **プレフィックス**：テナントのURLプレフィックスを更新（一意性を確保する必要があります）
- **説明**：テナントの説明を更新
- **ステータス**：テナントを有効または無効にする

リクエスト例：

```json
{
  "name": "tenant1",
  "prefix": "/new-prefix",
  "description": "更新された説明",
  "isActive": true
}
```

### テナントの削除

テナントを削除すると、そのテナントに関連するすべての設定が削除されます。この操作は元に戻せないため、注意してください。

### テナントの照会

特定のテナントの詳細情報を照会したり、すべてのテナントをリストしたりできます。

## テナントとユーザーの関連付け

テナントは特定のユーザーと関連付けることができ、以下の機能が有効になります：

- ユーザーは関連付けられたテナントのみにアクセスして管理できる
- 管理者はユーザーに複数のテナントアクセス権限を割り当てることができる
- ユーザーはゲートウェイ管理インターフェイスでテナントを切り替えることができる

## テナントセレクター

ゲートウェイ管理インターフェイスにはテナントセレクター機能が用意されており、ユーザーは以下のことができます：

- アクセス権限を持つすべてのテナントを表示する
- 現在の操作のためにテナントを切り替える
- 現在のテナントの設定とステータスを表示する

## ルートプレフィックス検証

異なるテナント間でルートが競合しないようにするため、システムはプレフィックス検証を実行します：

- 同じテナント内のルートプレフィックスは一意である必要があります
- 異なるテナント間のルートプレフィックスは競合を避ける必要があります
- ルートの作成または更新時に検証が自動的に実行されます

## ベストプラクティス

- 異なるビジネスシナリオやチームのために別々のテナントを作成する
- 識別と管理を容易にするために意味のあるテナント名とプレフィックスを使用する
- セキュリティを確保するためにテナント権限を定期的に確認する
- 分離を維持するために開発環境とテスト環境に異なるテナントを使用する
